# SPPS Planner V9.0.0 — AI/ML 성능 및 GUI 안정성 개선

**개발 소스 검증 문서 / 2026-11-09. 버전 표기 V9.0.0 유지.**

## 변경 목적

기존 Excel AI 창에서 파일 파싱, 정리, 데이터 병합/감사, 로컬 데이터 저장/복원, RandomForest 학습, 안전 JSON 모델 확인 및 유사 실험 검색이 Tkinter 메인 이벤트 스레드를 장시간 점유할 수 있었다. 특히 다량의 Excel 행이나 복잡한 모델에서는 버튼/스크롤 반응이 늦어질 수 있다.

## 변경 사항

- `suite_gui/ai_background_v9.py`: 단일 실행(single-flight) 백그라운드 작업기. 작업 스레드는 Tk 위젯에 접근하지 않으며, `Tk.after()` 폴링으로 성공/실패 결과만 메인 스레드에 전달한다. 중복 작업 실행 제한, 진행 표시 및 창을 닫은 뒤 늦게 도착한 결과 무시.
- `suite_gui/ai_excel_dialog_v9.py`: Excel Preview, Check & clean, Audit, Combine, Save/Append, Backup Restore, Train, Compare를 비동기 처리한다. 저장 전 동의와 Auto Plan에 AI 근거 첨부하는 동작은 메인 스레드에서 실행하며, 실험용 모델의 계산 결과가 합성 조건을 자동 변경하지 않는다.
- `suite_gui/ai_safe_forest_v9.py`: 크기·SHA-256 확인은 매번 수행하되, 검증을 마친 JSON 트리 구조의 파싱 결과를 최대 2개 재사용. SHA-256이 같은 바이트열만 캐시 공유할 수 있다. 모델은 실행 파일이 아닌 데이터 전용 JSON이며 joblib/pickle을 사용하지 않는다.
- `suite_gui/ai_excel_core_v9.py`: 여러 번 등장하는 화학 서열의 검증된 잔기 식별자를 최대 4096개 캐시하고, 리스트 복사로 호출자 변조 방지. 대량 실험의 유사도 탐색에서 `iterrows` 대신 `itertuples`를 사용하고 공통 조건은 한 번만 전처리한다. 정렬/거리 및 위험 보류 원칙 유지.
- `tests/test_v9_ai_nonblocking_cache.py`: 이벤트 루프 진행, 동시 제출 차단, 창 닫기, 손상된 모델·mtime 동일한 변조 탐지, 잔기 캐시 안정성 검증.
- 기존 GUI 워크플로우 테스트는 비동기 동작에서 완료 신호를 기다리도록 수정했다.

## 실험적 성능 측정

- 동일한 4,500행의 합성 **가상 데이터**에서 `similar_runs` 3회 측정, 같은 Linux Python 3.13 환경: 이전 코드 중앙 약 **1.322초**, 개선 코드 중앙 약 **0.791초** (약 40% 단축). 환경과 데이터에 따라 달라지는 단일 마이크로벤치마크 결과이며 전반적인 GUI/학습 성능이나 실험적 예측 정확도 상승을 증명하지 않는다.
- UI의 작업 스레드 분리는 학습 자체를 빠르게 만든다는 뜻이 아니라 **실행 중 GUI 응답성을 유지**하는 변경이다. 진행바는 작업 상태 표시이며 정확한 완료율이나 중단 기능은 아니다.

## 유지 및 한계

- 화학 `engine.py`와 제품 MW, stoichiometry, Check List 규칙은 이 변경에서 의도적으로 변경하지 않았다.
- Public과 Private 기본 데이터 분리 원칙을 지키고, 사용자가 선택한 파일은 로컬에서만 읽는다. 데이터 업로드/LLM API 기능은 없다.
- GUI 창을 닫아도 이미 진행 중인 학습을 즉시 강제 중지하지는 못한다. 완료되기 전에 Python 프로세스 자체가 종료되면 학습 결과가 생성되지 않을 수 있다. 저장은 기존 원자적 JSON 방식이다.
- 실제 Windows EXE/Installer 장시간 동작, 실제 대규모 Excel 데이터에서의 처리시간, 과학적 수득률 예측 성능은 별도 실환경 검증이 필요하다.
